各ZIPに `PACKAGE-README.md`、必要なライセンス文書、検証記録、`PACKAGE-SHA256.json` を同梱します。ZIP内の `specimen/index.html` はそのZIP内の資産を使います。各ZIPを別々のフォルダーへ展開し、案内に従って開いてください。他のZIPと同じディレクトリに上書き統合する必要はありません。source ZIPはTTF利用の前提ではありません。

配布パッケージの軽量見本と、リポジトリ全体の `build/family/specimen/index.html` は別です。後者は完全なビルドツリーの相対パスを前提にしています。両方のブラウザー動作を検証するまで「UI確認済み」としません。

## 梱包手順

依存関係は `requirements-family.txt` の固定版を使います。まず現在のソースと実際の成果物を検証し、その結果を使って梱包します。過去の日付の合格報告だけをコピーして梱包の根拠にしません。

```sh
python family/tools/priority_glyph_qa.py
python verify_family.py --report build/family/reports/full-tests.json
python family/tools/package_family.py dist --channel rc --version 2.0.0-rc.1
```

`dist` は生成先の例です。明示リストにない作業ファイル、参考フォント、`.git`、仮想環境、秘密情報、過去のZIPは収録対象にしません。ZIP生成はローカル処理で、公開操作をしません。

## RCと正式版の判定

検証記録は、対象の現在の成果物ハッシュと結び付いている必要があります。ソース/成果物が変わった後は再検証します。欠落、失敗、スキップ、古い成果物を対象にした報告を、現在の合格に置き換えません。優先QAや見本の生成も入力変更なので、必ず最終検証より前に行います。`PACKAGE-SHA256.json` は内容の照合用で、発行者の電子署名ではありません。

- RC: 構造・整合性の検査は合格が必要です。未実施のプラットフォーム/ブラウザー/視覚ゲートは、未実施であることを開示します。記録された失敗を黙って無視しません。既知の小サイズ同形と拡張字形未校正を明示した実験版のままです。
- 正式版: Windows導入、macOS導入、macOS構造検査、Linux/Fontconfig、ブラウザー見本、優先字形レビューの6ゲートを、対応する成果物と証拠で満たす必要があります。実験的拡張字形や既知の品質制限を残す場合は、その範囲を明示して承認する必要があります。`--channel release` だけで確認を省略せず、正式な配布と全日本語字形の完成を混同しません。

機械的な検査成功と、日本語字体の正しさ・可読性は別の判定です。優先11字の調査は全字の校正の代わりにはなりません。ゲートの現状は `family/release-gates.json` と梱包時の検証記録が正本です。macOS構造検査は、円形7記号の座標固定後に実macOSで再実行するまで未完了です。ゲート証拠の成果物集合ハッシュは自己参照を避けるためbuild-summaryや報告/見本を除外しますが、梱包検証自体はそれらも個別のハッシュで結び付けます。`japanese_typographic_release_ready` は、構造検査や限定的な優先字形レビューだけではtrueにしません。

## ソースとライセンス

4分割は利用目的の分離です。ライセンスは変更していません。バイナリだけのZIPも、対応する同版source ZIPと[出典・適用範囲](../NOTICE.md)を併せて案内してください。AGPL、CJKVI/CHISE関連、Unicodeの通知を、全成果物に単一の自由なフォントライセンスが適用されるかのように置き換えないでください。
