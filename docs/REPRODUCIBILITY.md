# V2中心線の再現性

2026年10月7日。対象はmain `f2bc9ebd76a9c3e45cac525d73f01d09d218cfcb` の7記号（◉、◐、◑、◒、◓、☎、⦿）。

## 確認できたこと

ユーザーのmacOS調査では7記号の中心線JSONハッシュが不一致で、SVGと同じ小数4桁では一致していました。本修正のLinux x86_64 / CPython 3.12.14 / glibc 2.41では、修正前の全12,776グリフについて同梱出典ハッシュと一致しました。Macの丸め前座標はこの環境にないため、OS差の厳密な対照実験による原因確定とは扱いません。

## 修正方式

`family/data/jis-circle-paths.json` に、元のプロジェクト独自設計から評価した7記号の座標を全精度で固定しました。JSONの十進表記はbinary64へ往復変換できる精度を保持し、整数と浮動小数点の型も保持しています。描画・出典・SVG・TTF・ビットマップは、同じ固定座標を入力とします。この7記号の生成でプラットフォームの `sin` / `cos` を呼びません。

出典ハッシュ方式は既存と同じ `SHA-256(json.dumps(paths, separators=(',', ':')).encode('utf-8'))` です。ハッシュだけを丸めたり、期待値だけを差し替えたりしていません。SVGの表示上の座標精度4桁と、出典JSONの全精度は区別します。

## 回帰検査

- 固定後の7記号の全精度中心線と既存出典ハッシュの一致
- `sin` / `cos` が例外を投げる環境でJISモジュールを再読込しても全7記号が同一
- 円環の外径・内径、閉じた輪郭、半円の向き、返された座標を変更しても原本を壊さないこと
- 全静的TTF・可変端点・32ストライクと、現在の生成ソースとの従来の構造／画素検査

`python -m pytest tests/test_circle_reproducibility.py` は依存する固定データも検査します。Linux/macOSの同一Python・固定依存による全検査を `.github/workflows/family-validation.yml` で実行します。設定の存在は実行成功の証拠ではありません。PRの対象コミットと一致する両OSの実行結果を確認してください。

## 公開判断との区別

構造検査の成功は字形の全数校正、OSアプリの操作確認、Font Bookの合格を意味しません。既知のMac失敗は修正対象として記録し、修正後のMac検査結果が得られるまで再検証待ちです。利用者のMacへインストールする操作はこの変更に含みません。

## 今後の追加規則

円・曲線を追加するときも、配布用の最終座標をレビュー可能な固定データとして保存してください。評価に用いた設計式・環境・元リビジョンを記録し、既存座標と同じbinary64往復精度を維持します。値や精度を変更する場合は字形変更として扱い、出典・SVG・TTF・ビットマップを同じソースから生成して両OSの検証を再実行します。期待ハッシュだけの更新は不可です。

## CIのPython導入

2026年10月7日の最初のMac CIはフォント検査前に停止しました。`actions/setup-python` の公式マニフェストにmacOS arm64版3.12.14がないためです。CIは公式 `astral-sh/setup-uv@v7`（uv 0.12.19）へ切り替え、Linux/macOSともPython3.12.14と同じ固定依存を使用します。[Astralの20260929配布](https://github.com/astral-sh/python-build-standalone/releases/tag/20260929)には該当するmacOS arm64版が含まれます。最初の準備失敗をフォントテスト失敗／成功として扱いません。
